## 4. Docker services

- **Postgres**: dev only today (see finding 6). Prod: internal network, strong secret password, least-privilege roles (the API user should not own schemas/DDL; migrations use a separate role), `app` schema backups as in PLAN.md "Backup policy".
- **ALPR (Python/FastAPI)**: processes untrusted images (OpenCV/ONNX = large parsing surface). Keep it unreachable from the internet (only the API calls it), run as non-root, read-only FS, memory/CPU limits, request size limit (the API already caps uploads at 4 MB; add the same in the ALPR app), pin `requirements.txt` hashes.
- **Images**: pin by digest, rebuild monthly, scan with Trivy (§6).
- **Secrets**: never `ENV`/`ARG` in a Dockerfile; use env files outside git or Docker secrets. `.env*` are already gitignored (only `*.example` tracked).

## 5. Rules for every new feature (add to PR/commit review)

1. New `/api` endpoint: Zod input, a `@Throttle` if it enumerates, `SessionGuard`/`AdminGuard` if it touches user data.
2. User data queries always `where userId = session.user.id`; never trust a client-supplied owner id.
3. No `fetch` of a URL taken from a request; fixed host + `encodeURIComponent`d parts, a timeout, and a response size cap.
4. No raw-HTML sinks; no `sql.raw` with request-derived text; no `child_process` with a shell.
5. New embed/third-party origin → add it to the CSP allow-list and note why.
6. New cookie → `HttpOnly; Secure; SameSite`. New redirect target → relative paths only.
7. Don't log secrets, tokens, full plates tied to a user, or request bodies of auth routes.
