# Prozorro.Sale vehicle auctions (plan)

Drafted 2026-10-31. **Status: not started.** Extends the SETAM auctions work in `docs/garpun-auctions-plan.md` (its "Later" step 12). Nothing is written yet except this plan.

## Findings (verified 2026-10-31, live probes)

- **API:** `https://procedure.prozorro.sale/api/search/byDateModified/<ISO date>?limit=100` returns full auction objects, no key. Page by passing the last `dateModified` (cut to 26 chars, no `Z`) as the next date. Feed starts April 2017. `public.api.openprocurement.org/api/2.5/auctions` is 404: do not use it. The feed has no count endpoint and no server-side filter (a `sellingMethod` query param was ignored).
- **Rate:** about 700 modified auctions a day in 2026 (330-670 on sampled days, 137-174 in 2023-24). October 2026: 22 674 records, 22 445 unique auctions, 365 vehicle-like, 245 with a VIN or plate in the text. Requests answer in 160-280 ms; parallel requests to the tenders API gave 429, so crawl sequentially with retry.
- **Same data as SETAM? No.** Different platform and IDs. Only 6 vehicles (7 auctions) of October overlap with `registry.auction_lots`, all bankruptcy cases (`bankRuptcy-*`), listed at different times and prices, so they are separate auctions of one vehicle, not duplicates. Whether a Prozorro auction and a SETAM lot are ever the same sale is **not** known.
- **Seller mix (Oct, vehicle-like):** customs resales `basicSell-*` 157, bankruptcy ~100, alienation 52, commercial 32, privatization 10, leases 10. `owner` is the electronic platform (e.g. `unitender.com.ua`), not the seller; `relatedOrganizations` was empty on the vehicle examples checked.
- **Fields per vehicle item:** `itemProps` (`itemPropsType: vehicle`): `identificationNumber`, `brand`, `model`, `productionYear`, `color`, `kilometrage`, `fuelType`, `engineCapacity`, `transmission`, `condition`, `damagePresence`, `damagedDescription` (not every auction has all of them; a commercial lot had only year and damage). Also `address.region` + locality, `location` lat/lon, CAV code `34...`. Auction level: `value`, `minimalStep`, `guarantee`, `tenderPeriod`, `auctionPeriod.startDate`, `status`, `awards[]`, `documents[]`, `description` (carries the case number and liquidator for bankruptcy).
- **Photos:** 210 of 216 vehicle-like auctions had images, avg 7.5 (`documentType: illustration`, `image/*`, mostly JPEG). Public URL `https://procedure.prozorro.sale/api/documents/public/<id>` returned 200 `image/jpeg` ~250 KB without login. URL lifetime not checked.
- **Plate is free text only.** VIN has a structured field (`identificationNumber`, can carry a trailing space), plate does not; the Volvo has it in the description, the Renault's plate was not in the text printed.
- **Link:** `https://prozorro.sale/auction/<auctionId>/` with the **full ID incl. prefix** (`BRE001-...`). A dropped prefix gives a 404 page.
- **Estimated size:** 700-900k feed records in total (the 2017-2022 volume is not sampled), 5 000-15 000 vehicle auctions with a plate or VIN. Backfill 30-60 min once; the daily run is under 10 requests.

## Decisions (user, 2026-10-31, from the discussion)

1. Ingest **only auctions with a plate or VIN** (a vehicle CAV/keyword test plus an identifier). The rest cannot be looked up.
2. **Separate table** `registry.prozorro_auctions` next to `registry.auction_lots`; the API merges them. No `source` column on `auction_lots`.
3. Daily scan with a `dateModified` cursor, not monthly.
4. One **combined section** (plate card, VIN page, `/auctions`), a source chip per lot, category chips from the selling method, each lot links to its own auction page.
5. Two sources for one plate/VIN: **separate lots, merged vehicle facts**. Show the richer value, and every distinct field once. Conflicts show both values.
6. Photos shown from Prozorro by URL first; local copies are a later step.

## Steps (each ends verified; a later step can start any day)

Read first: `docs/features-reference.md` "Auction history", "Agent discovery, edge cache, Zod and CSP"; `scripts/src/auctions.ts` + `auctions-parse.ts` (pattern to copy); `SCHEDULE.md`; `packages/shared/src/auctions.ts`.

1. [ ] **Migration `0085_prozorro_auctions.sql`** (new table only, backward compatible). Columns: `auction_id text PRIMARY KEY` (full ID), `selling_method`, `status`, `value`, `minimal_step`, `guarantee`, `final_price` (active award), `auction_start`, `tender_start`, `tender_end`, `plate`, `vin`, `make`, `model`, `year`, `color`, `kilometrage`, `fuel`, `engine_cc`, `transmission`, `condition`, `damaged`, `damage_text`, `region`, `locality`, `lat`, `lon`, `title_raw`, `description_raw`, `photo_urls jsonb`, `source_modified_at timestamptz`, `first_seen_at`, `updated_at`. Indexes on `plate` and `vin` (partial, as in `0084`), `status`, `auction_start`. Re-ingestable, so not in seed CSVs or `backup.sh`; check whether `IRREPLACEABLE` needs no entry.
2. [ ] **Parser `scripts/src/prozorro-parse.ts` + tests.** Pure function: raw auction object (Zod, `.nullable().optional()` on every item prop) to a row or `null`. Vehicle test: CAV `341`-`343` or item `itemPropsType: vehicle` or the keywords used in the crawl. VIN from `identificationNumber` (trim, uppercase) else a 17-char regex excluding I O Q; plate via `normalizePlate` from `@carplates/shared`, never a new regex for the logic. Reject measurement look-alikes (the `1896 см` case). Several vehicles in one auction: check how common first; if rare, take the first and log a count.
   Tests from fixtures of the real cases found: Renault 11GTA (`BRE001-UA-20260924-95103`), Volvo 460 half share (`BRE001-UA-20261002-41938`), the Dnipro Dokker (trailing space in VIN), a commercial lot with partial props, a building (rejected), an `Автобус` without identifier (rejected).
3. [ ] **Ingest CLI `scripts/src/prozorro.ts`** (`pnpm ingest:prozorro [--from DATE] [--to DATE]`). Sequential paging, retry with backoff on 429/5xx, `INSERT ... ON CONFLICT (auction_id) DO UPDATE` when `source_modified_at` is newer. Default `--from` = `max(source_modified_at)` minus 1 day, so the daily run needs no flag. Print counts: records read, vehicle-like, with identifier, inserted, updated, rejected by reason.
4. [ ] **Backfill.** First the last 12 months (about 25 min), look at the counts and 10 real rows by hand, then 2017 to now. Report the real totals here (replace the estimates above). No `TRUNCATE` is involved; run `SELECT count(*) FROM registry.prozorro_auctions` before and after.
5. [ ] **Schedule.** Job `prozorro-auctions` in `jobs.ts` and `run-ingest.sh`; cron in `infra/vps/ingest.cron` after the `auctions` slot; `SCHEDULE.md`, `docs/deploy.md`, healthchecks note. Deploy order as for Garpun: merge, API deploy runs the migration, `deploy-ingest` installs the cron, run `run-ingest.sh prozorro-auctions` once on the VPS for the backfill.
6. [ ] **Shared contract + API.** New fields in `packages/shared/src/auctions.ts` (its own file, so new fields are `.nullable().optional()` and saved offline data survives); rebuild with `pnpm --filter @carplates/shared build`. `auctions.service.ts` reads both tables for a plate or VIN and returns one list: `source: 'setam' | 'prozorro'`, `category` (from `selling_method`: customs, bankruptcy, privatization, state property, other), `url`, photos, the new vehicle fields. `/auctions` list and stats include both with a source filter. Keep the `common/cache.ts` headers and the offline cache entry for the changed query.
7. [ ] **Vehicle facts merge (API side, tested).** Per VIN or plate, one `vehicle` object: each field once; precedence Prozorro structured value over SETAM parsed title; where the two differ (year, make, model) keep both values and flag it. Auction lots are never merged. Tests with the two real overlap vehicles (Renault `VF611GTA000122884`, Volvo `XLBLX183EMC210919`).
8. [ ] **UI.** `UaAuctionLot.tsx` and the `/auctions` list: source chip, category chip, link to the lot's own page (`prozorro.sale/auction/<id>/` or the SETAM link), photo strip (lazy, `alt` text, no hotlink failure crash), damage note, specs from the merged vehicle block. Filters for source and category in `use-auction-filters.ts`. Chart/timeline: Prozorro lots join the same price history, labelled by source. i18n ua/ru/en, `-` instead of an em dash in UI strings. Add new `sections` ids only if a new shareable section appears (none planned).
9. [ ] **Docs and close-out.** `docs/features-reference.md` (new source, merge rule, link format), `docs/plan-done.md` write-up, one-line ✅ in `PLAN.md`, `releases.ts` item (new day means bump `releases/latest.ts`), About `SOURCES` + `about.source.*` (ua/ru/en), `/read/auctions` guide text if it names sources, `pnpm format`, suggested commit message. Give example plates and VINs (both sources, Prozorro only, damaged, many photos).
10. [ ] **Later.** Copy photos to our own storage (size and licence to check first, about 7 x 250 KB per auction); seller/organizer fields if `relatedOrganizations` turns out to carry them for other methods; the other Prozorro lot types (leases) are out of scope.
